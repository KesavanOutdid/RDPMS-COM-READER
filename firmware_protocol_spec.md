# CAN Bus Firmware Update Protocol Specification

This document outlines the protocol implemented by the PC host software for transferring firmware updates over the CAN bus. It is intended for the embedded engineering team to implement the receiving logic on the microcontroller.

## 1. Protocol Overview
The firmware upload uses a request-acknowledge ping-pong mechanism. 
1. The PC sends a **Header Frame** containing file metadata.
2. The Embedded Device verifies the header and sends an **ACK** (or **Error**).
3. The PC sequentially sends **Data Frames** containing the firmware binary.
4. The Embedded Device verifies each chunk and sends an **ACK** (or **Error**) after each frame.

> **CRITICAL NOTE ON ENDIANNESS:** 
> While the standard CAN frame wrapper ID uses Little-Endian, **all multi-byte fields within the firmware update payloads (Size, CRC, Frame Index) are transmitted in BIG-ENDIAN (Most Significant Byte First).**

---

## 2. Checksum Algorithm
All CRCs used in this protocol are **CRC-16/Modbus**.
*   **Polynomial:** `0x8005` (Reversed: `0xA001`)
*   **Initial Value:** `0xFFFF`
*   **Byte Order:** Transmitted in **Big-Endian** format `[High Byte, Low Byte]` within the payload.

---

## 3. Transmission Phases

### Phase 1: The Header Frame
The PC initiates the upload by sending an 8-byte payload containing the firmware metadata.

**Payload Structure (8 Bytes total):**
| Byte Index | Length | Description | Endianness |
| :--- | :--- | :--- | :--- |
| `0 - 3` | 4 bytes | **Total File Size** in bytes | Big-Endian `[Highest...Lowest]` |
| `4 - 5` | 2 bytes | **Total Frame Count** (Total chunks) | Big-Endian `[High, Low]` |
| `6 - 7` | 2 bytes | **Overall File CRC-16** (Over entire bin) | Big-Endian `[High, Low]` |

### Phase 2: Data Frames
Following a successful Header ACK, the PC sends the firmware data. The PC splits the file into chunks of up to 60 bytes. The logical payload generated by the PC is exactly 64 bytes.
*(Note: If operating on Classic CAN, the host software will automatically fragment this 64-byte payload into eight sequential 8-byte CAN frames. The embedded side must reconstruct the 64-byte block before processing).*

**Payload Structure (64 Bytes total):**
| Byte Index | Length | Description | Endianness |
| :--- | :--- | :--- | :--- |
| `0 - 1` | 2 bytes | **Frame Index** (Starts at `0x0000`) | Big-Endian `[High, Low]` |
| `2 - 61` | 60 bytes | **Firmware Data** chunk | N/A (Raw bytes) |
| `62 - 63` | 2 bytes | **Frame CRC-16** | Big-Endian `[High, Low]` |

*Important: The Frame CRC is computed ONLY over the first 62 bytes of that specific payload (Index + Data).*

---

## 4. Acknowledgment (ACK) Requirements

After receiving **any** Header Frame or Data Frame block, the embedded device **must** respond with a CAN frame back to the PC to indicate success or failure.

*   **Timeout:** The PC waits a maximum of **30 seconds** for an ACK. If no response is received, the update is aborted.
*   **Success (ACK):** The embedded device must send a CAN frame where the first byte of the data payload is `0x79`.
*   **Error (NACK):** The embedded device must send a CAN frame where the first byte of the data payload is `0xE1`.

### Acknowledgment Flow:
1. PC sends Header Frame -> Embedded replies with `0x79...` (Ready for data)
2. PC sends Data Frame `0` -> Embedded verifies CRC, writes to flash, replies with `0x79...`
3. PC sends Data Frame `1` -> Embedded verifies CRC, writes to flash, replies with `0x79...`
4. ... repeats until Frame Count is reached.
5. Upload Complete.

---

## 5. Summary Checklist for Embedded Developers
- [ ] Parse multi-byte fields (Size, CRC, Index) assuming **Big-Endian** arrangement.
- [ ] Reconstruct 64-byte payload buffers if receiving via Classic CAN (8-byte packets).
- [ ] Calculate CRC-16/Modbus over bytes `0-61` of the Data Frame and compare it against bytes `62-63` (remembering `62` is high-byte).
- [ ] Transmit `0x79` as the first byte of your CAN response immediately after successfully processing a block.
- [ ] Transmit `0xE1` to intentionally abort the PC-side process if a CRC fails or flash writing fails.
